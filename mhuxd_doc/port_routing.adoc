== Port Routing

=== About Ports
Similar to the virtual COM ports of the microHam Windows Device Router mhuxd can provide virtual serial ports (VSP). VSPs are implemented using the Linux CUSE driver, hence the cuse kernel module must be loaded and the device /dev/cuse must exist.

Alternatively mhuxd also offers TCP/IP network ports (IPv4 and IPv6).

Ports persist even when the keyer is switched off or unplugged. Applications can keep them open meanwhile.

=== Port Page
To access the port page select tab “Daemon”, menu “Ports”. The first section, “Port Config”, shows the configured ports with their settings. With a new mhuxd installation this list is empty. Ports can be removed here by selecting them and pushing the “Remove” button.

.Port Config with ports for a micro KEYER III

The *Transceive / AI* column applies to CAT ports, see below. Whether a port works and which application has it open is shown in the Port List on the Summary page, see <<the_webui>>.

To create a port press the “Add” button. A dialog opens in which you choose the port type, the keyer to route to, the destination channel and the type-specific options described below. There are 2 types of ports available:

* VSP – virtual serial port
* TCP – TCP/IP network port

Press “Create” to add the port, or “Cancel” to discard.

=== Destination Channels

The *Destination Channel* is the keyer channel the port is connected to. Only the channels of the selected keyer are offered:

[cols="1,4"]
|===
| Channel | Use

| CAT1, CAT2 | CAT commands to the radio (CAT2: second radio of the MK2R/MK2R+)
| PTT1, PTT2 | PTT keying by applications, see below
| WK         | K1EL Winkey chip (CW)
| FSK1, FSK2 | FSK (RTTY) keying
| AUX        | AUX serial port (micro KEYER II/III, Station Master)
| MCP        | microHam control protocol (MCP) commands
| ROTATOR    | rotator control (Station Master)
|===

=== Add a VSP Port
Select the *VSP* port type, the keyer the port should be routed to and the *Destination Channel*.

Specify the device name. VSP devices are always located in `/dev/mhuxd/`. The dialog suggests the channel name, e.g. `cat1`. Optionally you may select “PTT via RTS” and/or “PTT via DTR”. With this option set an application can key the PTT using the RTS and/or DTR signals.

It is not suggested to use PTT/RTS or PTT/DTR on the CAT channel. Better use a dedicated PTT VSP device (e.g. `/dev/mhuxd/ptt1`) and route it to the PTT channel.

Many applications build their list of serial ports from `/dev/serial/by-id/` (e.g. fldigi, Hamlib, QLog). The udev rule of mhuxd therefore publishes every VSP there as well, e.g. `/dev/mhuxd/cat1` as `/dev/serial/by-id/mhuxd-cat1`. If an application still doesn't list a VSP, you can usually type its path.

=== Add a TCP Port
Select the *TCP* port type, the keyer to route to and the destination channel, then enter a TCP port number. You may select “Remote Accessible”. This would allow other computers to connect to this port. [red]#Don’t do this if your computer is directly connected to the internet or in an insecure network!#

On a PTT channel, a TCP port keys PTT with the byte 0x01 and releases it with 0x00.

A port takes one application at a time, a second one is turned away: a virtual serial port fails to open with EBUSY, a TCP connection is closed. To share the radio between applications, give each its own port, see <<native_multi_client>>.

=== Common Options

* *Transceive / AI* (CAT ports only, on by default) – when switched off, the port doesn't get CI-V transceive and Auto Information messages, only the answers to its own commands. This needs RIG Mode Sync with backend “native”, see <<native_transceive>>.

=== PTT and closed ports

When an application closes a port, or its TCP connection drops, while it holds PTT, mhuxd releases the PTT.
